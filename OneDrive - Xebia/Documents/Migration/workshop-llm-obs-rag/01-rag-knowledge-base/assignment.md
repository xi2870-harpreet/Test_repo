In this two-part lab, you'll upgrade the chatbot to add a Retrieval-Augmented Generation (RAG) pipeline, providing context to user queries from a knowledge base of up-to-date company information.

Here's the user story guiding the upgrade:

> "As a time-traveler planning my adventure, I want the chatbot to tell me accurate information about travel package details, pricing, and company policies, so that I can make informed decisions for a safe and enjoyable trip."

Part one, this activity, focuses on setting up the knowledge base service and creating a searchable store of QuantumHound-specific information. In part two, you'll implement the retrieval and response generation steps of the RAG workflow.

### Learning objectives

In this lab activity, you'll do the following:

- Implement a searchable knowledge base using a local embedding model and a vector database
- Instrument the knowledge base service with Datadog to see span-level trace data for each step in the document ingestion and embedding process

Throughout this lab, you'll use Datadog's Agent Observability to track the document ingestion and embedding process as you put the components together.

Step 2: Create a knowledge base
===

While the system prompt improves the relevance of responses, it isn't a scalable or cost-effective solution for providing reliable and up-to-date information about the company's policies and offerings.

To improve the chatbot's accuracy, you'll create a knowledge base containing QuantumHound's policies, technology, and travel package details. The knowledge base will serve as a searchable source of truth to inform the LLM's responses.

Step 3: Instrument the knowledge base service for Agent Observability
===

Follow the steps below to manually instrument the QuantumHound application's embedding process.

First, you'll import the `LLMObs` class from `ddtrace`, configure Agent Observability in the code, and add the required environment variables.

The Datadog Python tracing library has already been included in `requirements.txt` for the knowledge base service, so you don't need to add `ddtrace` manually.

1. In the [IDE](tab-1), open `kb-service/ingest_documents.py`.

    Below the existing imports, add the following import statement:

    ```python
    from ddtrace.llmobs import LLMObs
    ```

1. In the same file, below the import line you just added, and above the first function definition, add the following code to enable Agent Observability:

    ```python
    LLMObs.enable(
      ml_app=os.getenv("DD_LLMOBS_ML_APP"),
      api_key=os.getenv("DD_API_KEY"),
      site=os.getenv("DD_SITE"),
      agentless_enabled=os.getenv("DD_LLMOBS_AGENTLESS_ENABLED"), # optional
    )
    ```

    These environment variables will be set in `docker-compose.yml`, which you'll update in the next step.

    >[!NOTE]
    > The `agentless_enabled` argument is not required, as the tracing library will automatically detect whether a compatible agent is present. When unset, it will default to `None`.

1. Open the `docker-compose.yml` file and add the following environment variables to the `kb_service` service definition, nested below `environment` on line 119:

    ```yaml
    - DD_SITE=${DD_SITE}
    - DD_API_KEY=${DD_API_KEY}
    - DD_LLMOBS_ML_APP=quantumhound-chatbot
    - DD_LLMOBS_AGENTLESS_ENABLED=1 # optional
    # Datadog env vars always recommended
    - DD_ENV=${DD_ENV:-qh-local}
    - DD_SERVICE=${DD_SERVICE:-quantumhound-kb}
    - DD_VERSION=${DD_VERSION:-1.0.0}
    ```

    >[!IMPORTANT]
    > After copying and pasting the code, make sure to check the indentation. The `environment` section should be indented to match the other environment variables in the `kb_service` service definition. Indentation is important in YAML files, and mistakes in indentation can cause errors when starting the service.

    <br>

    Next you'll use decorators from the `ddtrace.llmobs.decorators` module to trace specific functions. Each decorator assigns a span kind that defines the type of operation being performed, such as `embedding`, `tool`, or `workflow`. You'll instrument functions that perform key operations in the knowledge base service: embedding creation, document storage, and document processing.

1. In `kb-service/ingest_documents.py`, below the existing imports, add the following import statement:

    ```python
    from ddtrace.llmobs.decorators import workflow, tool, embedding
    ```

1. In `kb-service/ingest_documents.py`, locate the `create_document_embeddings` function that handles embedding creation (around line 20-22).

    This function creates vector embeddings of documents, which is a key operation in transforming text into a format suitable for retrieval.

1. Add the `@embedding` decorator above the function definition to instrument it with an embedding span.

    ```python
    @embedding
    ```

    The code should look like this:

    ```python,nocopy
    @embedding
    def create_document_embeddings(
        document: str, topic: str
    ) -> Tuple[List[float], Dict[str, str]]:
        # ...
    ```

    All the decorators you'll add in the next few steps will follow the same pattern.

1. Next, locate the `store_document` function that is responsible for saving a document in the vector database (around line 35-37).

    This function stores the embeddings and metadata in the vector store. As an external service call, it's a good candidate for a tool span.

1. Add the `@tool` decorator above the function definition to instrument it with a tool span:

    ```python
    @tool
    ```

1. Finally, locate the `process_document` function that orchestrates all the steps you instrumented above (around line 48-50).

    This function represents the complete end-to-end process of document ingestion, coordinating multiple operations. As the entry point for the ingestion process, it should be instrumented with a workflow span.

1. Add the `@workflow` decorator above the function definition to instrument it with a workflow span:

    ```python
    @workflow
    ```

1. In the [terminal](tab-0), restart the knowledge base service to apply the changes:

    ```sh,run
    docker compose up -d --no-deps --force-recreate --build kb_service
    ```
